# 一、更新内容

1、优化json文件规则。移除重复规则；headers优化，避免重复判断或跳过headers；移除不必要的规则字段。

2、优化只判断了cookie的逻辑，所有header应判尽判；某些漏洞不需要判断那么多的header进行headers跳过，如LFI和upload

3、移除文件包含白名单。之前的白名单检查逻辑是以xxx文件开头匹配的，如?file=/assets/xxx，留着很鸡肋。如果有些靶场出现拦截情况，可以先关闭FI检测看是否放行。

4、ssrf的协议统一整合为一条正则，归FI中了

5、日志仍单文件存储，如果轮转日志，数据统计仍是单文件。所以，如果日志文件过大，势必影响性能，为避免不必要的问题，可以备份一下(改个名字即可)，每小时手动给原来的日志文件改个名字，之后再创建个新的WafLog.txt，并加权限

# 二、可能遇到的问题

1、日志记录不完整，检测规则未触发。如果是自己搭建的测试点，没有主动url编码，会出现日志记录不完整的情况。

# 三、缺陷及下一步规划

1、文件存储，导致日志数据必须一次性全部读取，重复读取，造成资源浪费。考虑采用SQLite设计数据库存储。

2、部署过程不够自动化。尝试写powershell和sh脚本，但是不好用。决定使用php操作SQLite进行部署。

3、ssrf如果访问其他地址，长时间不回应，如url=http://8.8.8.8，会导致waf长时间不反应，可以尝试中断ssrf请求后刷新waf，也可以重启web服务器。

4、文件上传内容检测规则写的没有很全面，写了后缀检测+升级中间件就可以拦截很多。

5、规则涉及编码绕过的，很多会匹配到rce，因为rce先执行。其他规则里面的编码匹配写的不如rce充足。
